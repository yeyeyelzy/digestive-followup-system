# 家属端（Family Side）开发方案

## 1. 项目概述
本方案旨在基于现有的 `wx_patient_final` 小程序结构和 `web_doctor_final` 后端逻辑，开发一套供患者家属使用的微信小程序。核心目标是实现家属对患者康复情况的监督与辅助，包括查看患者数据、接收预警及康复方案。

## 2. 数据库设计 (MySQL)

目前数据库中暂无 `family` 表，需要新增以下两张表来存储家属信息及家属与患者的绑定关系。

### 2.1 家属信息表 (`sys_family`)
用于存储家属的基本账户信息。

```sql
CREATE TABLE `sys_family` (
  `family_id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '家属ID',
  `family_name` varchar(30) DEFAULT '' COMMENT '家属姓名',
  `phone_number` varchar(11) DEFAULT '' COMMENT '手机号码（作为登录账号）',
  `password` varchar(100) DEFAULT '' COMMENT '密码',
  `avatar` varchar(255) DEFAULT '' COMMENT '头像路径',
  `gender` char(1) DEFAULT '0' COMMENT '性别（0男 1女 2未知）',
  `age` int(3) DEFAULT NULL COMMENT '年龄',
  `status` char(1) DEFAULT '0' COMMENT '帐号状态（0正常 1停用）',
  `del_flag` char(1) DEFAULT '0' COMMENT '删除标志（0代表存在 2代表删除）',
  `create_time` datetime DEFAULT NULL COMMENT '创建时间',
  `update_time` datetime DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`family_id`),
  UNIQUE KEY `uk_phone` (`phone_number`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='家属信息表';
```

### 2.2 患者-家属绑定关系表 (`sys_patient_family`)
用于维护家属与患者的多对多关系（一个家属可关注多名患者，一名患者可被多名家属关注）。

```sql
CREATE TABLE `sys_patient_family` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键',
  `family_id` bigint(20) NOT NULL COMMENT '家属ID',
  `patient_id` bigint(20) NOT NULL COMMENT '患者ID',
  `relationship` varchar(50) DEFAULT '' COMMENT '关系（如：父子、夫妻等）',
  `status` char(1) DEFAULT '0' COMMENT '绑定状态（0已绑定 1申请中 2已解绑/拒绝）',
  `create_time` datetime DEFAULT NULL COMMENT '绑定时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_bind` (`family_id`, `patient_id`) -- 防止重复绑定
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='患者家属关联表';
```

## 3. 后端开发方案 (Java Spring Boot)

后端逻辑将集成在现有的 `RuoYi-Vue` 后端工程中。

### 3.1 实体类与Mapper
1.  **Entity**: 创建 `SysFamily` 和 `SysPatientFamily` 实体类。
2.  **Mapper**:
    *   `SysFamilyMapper`: 实现基本的 CRUD 及根据手机号查询。
    *   `SysPatientFamilyMapper`: 实现绑定关系的增删改查，以及**根据 family_id 查询已绑定患者列表**的方法。

### 3.2 Service 层逻辑
1.  **用户管理 (`FamilyService`)**:
    *   登录/注册逻辑（参考 `PatientUserService`）。
    *   个人信息修改。
2.  **绑定逻辑 (`FamilyBindService`)**:
    *   **绑定方案/流程**:
        1.  家属在小程序输入**患者手机号**和**真实姓名**。
        2.  后端根据手机号和姓名校验患者是否存在 (`sys_patient` 表)。
        3.  若存在，在 `sys_patient_family` 表插入一条记录。
        4.  (可选优化) 若需要患者同意，状态设为 `1` (申请中)，患者端需增加“家属管理”功能进行确认；**MVP阶段建议简化为：校验身份证后四位或直接校验手机号姓名匹配即自动绑定成功 (状态 `0`)。**
    *   **解绑**: 将 `sys_patient_family` 表对应记录状态置为 `2` 或物理删除。

### 3.3 Controller 层接口 (`FamilyController`)
需提供以下接口供家属端小程序调用：
*   `/api/family/login`: 登录
*   `/api/family/register`: 注册
*   `/api/family/profile`: 获取/修改个人信息
*   `/api/family/bind`: 绑定患者 (参数: patientPhone, patientName, relationship)
*   `/api/family/unbind`: 解绑患者 (参数: patientId)
*   `/api/family/myPatients`: 获取已绑定的患者列表 (返回 List<PatientUser>)
*   `/api/family/patient/data`: 获取特定患者的健康数据 (复用现有 Service，但增加权限校验，确保 familyId 有权查看 patientId)。

## 4. 前端开发方案 (微信小程序)

前端项目将基于 `wx_patient_final` 进行**复制并改造**，命名为 `wx_family_final`。

### 4.1 目录结构调整
保持 `wx_patient_final` 结构，主要修改点如下：
*   `app.json`: 修改 `navigationBarTitleText` 为“web_doctor_家属端”。
*   `utils/request.js`: 保持不变，Token 存储逻辑可通用。

### 4.2 关键页面开发
1.  **登录/注册页 (`pages/login`, `pages/register`)**:
    *   复用现有界面，接口地址指向 `/api/family/...`。
2.  **主页 (`pages/my/index` 改造)**:
    *   参考患者端的“我的”界面。
    *   **核心功能区**:
        *   **顶部**: 显示当前选中的“关注患者”卡片（如果绑定多个，可切换）。
        *   **功能菜单 (Grid布局)**:
            *   [健康数据]: 跳转至数据查看页。
            *   [风险预警]: (待开发) 显示异常指标列表。
            *   [康复方案]: (待开发) 查看医生下发的指导。
            *   [绑定管理]: 跳转至绑定/解绑页面。
3.  **绑定管理页 (`pages/family/bind`)**:
    *   表单：输入患者姓名、手机号、关系。
    *   列表：展示“已绑定患者”，提供“解绑”按钮。
4.  **患者数据查看页**:
    *   复用 `wx_patient_final` 中的 `diet`, `behavior`, `medicine` 等页面。
    *   **修改点**: 入参增加 `patientId`。原患者端默认查询当前登录用户数据，家属端需将选中的 `patientId` 传给后端接口查询指定患者数据。

### 4.3 风险预警与康复方案 (后续开发)
*   **风险预警**: 后端定时任务分析患者数据，生成预警信息存入 `sys_warning` 表，家属端轮询或下拉刷新获取。
*   **康复方案**: 复用医生端下发给患者的方案数据，家属端仅做**只读展示**。

## 5. 权限与安全
*   **接口鉴权**: 家属端所有接口需校验 Header 中的 Token。
*   **数据隔离**: 家属只允许查看在 `sys_patient_family` 表中建立了有效绑定关系的患者数据。查询患者数据接口必须校验 `BindRelation(familyId, patientId)` 是否存在。

## 6. 开发步骤建议
1.  **数据库**: 执行 SQL 建表脚本。
2.  **后端**: 生成代码 (Entity/Mapper)，实现 Login/Register 接口。
3.  **前端**: 复制项目，通 Login/Register 流程。
4.  **后端**: 实现绑定接口 (Check & Insert)。
5.  **前端**: 完成绑定界面。
6.  **后端**: 改造/新增查询患者数据接口 (支持传入 patientId 并校验权限)。
7.  **前端**: 完成数据查看页面复用与联调。
