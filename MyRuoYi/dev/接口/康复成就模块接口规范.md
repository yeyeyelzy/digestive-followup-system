# 康复成就模块接口规范（患者端）

> 日期：2026-02-28  
> 说明：智能体后端只负责“是否健康生活”的综合判定，返回布尔值；成就等级由业务服务汇总计算后返回给小程序。

## 1. 智能体判定接口（布尔型）

- Method: `POST`
- Path: `/ai/recovery/healthy-life-decision`
- 作用：基于多维数据（打卡、指标、随访等）进行大模型综合判断，返回当日是否健康生活。

### 1.1 请求体

```json
{
  "patientId": "10086",
  "date": "2026-02-28",
  "inputs": {
    "dietCompleted": true,
    "behaviorCompleted": true,
    "medicineCompleted": true,
    "livingCompleted": true,
    "vitalsNormal": true,
    "notes": "可选补充文本"
  }
}
```

### 1.2 响应体（核心为布尔值）

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "patientId": "10086",
    "date": "2026-02-28",
    "isHealthyLife": true
  }
}
```

### 1.3 字段约束

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| patientId | string | 是 | 患者ID |
| date | string | 是 | 判定日期，格式 `yyyy-MM-dd` |
| isHealthyLife | boolean | 是 | 智能体综合判定结果 |

---

## 2. 成就汇总查询接口（聚合接口，若依后端对外）

- Method: `GET`
- Path: `/system/recovery-achievement/current`
- Query：`patientId`（可选，患者端可不传，按登录态解析）

### 2.1 字段来源划分（关键约束）

- `healthy_today`：来自智能体后端判定结果。
- 其余字段：来自若依后端业务库计算结果。
  - `current_title_id`
  - `current_title_name`
  - `current_level`
  - `consecutive_healthy_days`
  - `total_healthy_days`

### 2.2 推荐调用链路（若依内部）

1. 小程序调用若依聚合接口：`/system/recovery-achievement/current`。  
2. 若依查询本地业务库，拿到称号/等级/累计天数等字段。  
3. 若依调用智能体接口：`/ai/recovery/healthy-life-decision`，拿到 `isHealthyLife`。  
4. 若依组装统一响应：将 `isHealthyLife` 映射为 `healthy_today` 返回前端。

> 前端不直接调用智能体后端，统一由若依聚合并返回。

### 2.3 对外响应体（若依返回给小程序）

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "current_title_id": 1,
    "current_title_name": "康复萌新",
    "current_level": 3,
    "consecutive_healthy_days": 4,
    "total_healthy_days": 25,
    "healthy_today": true
  }
}
```

### 2.4 容错与一致性策略（建议）

- 若依库查询成功，但智能体短时失败：
  - 返回若依字段；
  - `healthy_today` 返回最近一次缓存值（无缓存则 `false`）；
  - `msg` 附加“智能体结果为缓存值”。
- 若依库失败：直接返回失败（`500`），不返回不完整成就数据。
- 建议若依记录 `healthy_today_source`（`realtime`/`cache`）用于排查，但不必对小程序暴露。

### 2.5 前端展示说明

- 进度条仍按 `consecutive_healthy_days / 7` 渲染。
- 今日状态展示使用 `healthy_today`。

---

## 3. 小程序现有接入点

- 请求封装：`patient/api/requests.js`
  - `getHealthyLifeDecision(patientId, date)`
  - `getRecoveryAchievement(patientId)`
- 页面展示：`patient/pages/my/index.*`
- 开关：`patient/app.js` 中 `enableRecoveryAchievementApi`（默认 `false`，走模拟数据）

---

## 4. 错误码建议

| code | 含义 | 前端处理 |
|---|---|---|
| 200 | 成功 | 正常渲染 |
| 400 | 参数错误 | toast 提示 |
| 401 | 登录失效 | 引导登录 |
| 404 | 患者不存在 | toast 提示 |
| 500 | 服务异常 | 回退模拟数据 |
