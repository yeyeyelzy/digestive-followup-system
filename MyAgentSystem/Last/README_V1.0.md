# 心脏康复多智能体系统 V1.0

## 一、版本定位与核心目标

本项目为**心脏康复多智能体监测与报告系统V1.0版本**，基于Fitabase可穿戴时序数据，结合心血管临床指南，通过多智能体架构与贝叶斯在线学习算法，实现心脏康复患者的全周期健康监测、动态风险分级、异常归因分析、多端差异化报告自动生成。

**核心目标**：替代人工康复评估，实现7*24小时自动化患者监测，为医护、患者、家属提供差异化的康复数据支撑，降低心血管不良事件风险。

## 二、V1.0版本已落地核心能力

| 能力分类 | 详细功能说明 |
|----------|-------------|
| **多源数据处理** | 支持秒级心率、分钟级步数/METs/睡眠、日级活动汇总、体重、海拔摔倒检测、视频摔倒识别7大类数据的自动化清洗、时间对齐、特征提取、医学合规性校验 |
| **在线学习与动态评估** | 落地带遗忘因子的贝叶斯在线更新算法，支持每日增量数据流式学习，自动更新患者个性化基线、三级风险区间、健康评分，实现病情好转/稳定/恶化的自动判定 |
| **多智能体协同决策** | 基于模块化架构实现多个智能体的全链路协同，解决多指标冲突、权重动态调整、医疗规则优先级管控问题，全流程可追溯、可审计 |
| **风险预警与异常归因** | 实现蓝/黄/红三级风险分级，精准区分生理性与病理性心率异常，支持心衰加重、心律失常、用药漏服、摔倒昏迷4大类高危事件的自动识别与预警 |
| **多端差异化报告生成** | 支持医护端、患者端、家属端三端差异化报告，自动生成日报、周报、月报，支持JSON、PDF两种格式导出，配套全量可视化图表 |
| **多场景接入能力** | 支持本地测试、若依框架集成、HTTP接口调用3种接入方式，适配开发测试、生产部署、第三方对接全场景 |

## 三、处理性能与边界说明

### 3.1 处理性能指标（基于4核8G服务器）

| 处理场景 | 性能指标 |
|----------|---------|
| 单患者单日数据处理 | 平均耗时<2秒，含数据处理、智能体计算、报告生成、PDF导出 |
| 单患者全周期（31天）数据处理 | 平均耗时<30秒，含全周期日报、5份周报、1份月报生成 |
| 批量患者处理（100患者单日数据） | 平均耗时<60秒，支持多线程并行处理 |
| HTTP接口响应 | 单患者评估接口TP99<3秒，报告查询接口TP99<500毫秒 |

### 3.2 V1.0版本处理边界

1. **数据周期**：支持2016-04-12至2016-05-12固定周期，可通过配置文件扩展任意时间周期；
2. **患者类型**：支持冠心病PCI术后、慢性心衰稳定期、心律失常射频消融术后3类核心心脏康复患者；
3. **数据格式**：仅支持CSV、XLSX、JSON格式的结构化时序数据；
4. **并发限制**：单实例支持最高100QPS的接口请求，超过需做集群部署；
5. **医疗边界**：所有评估结果仅为康复辅助参考，不替代临床医生的专业诊断。

## 四、快速开始指南

### 4.1 环境准备

```bash
# 克隆或下载项目
cd c:\Projects\大创\Ver4\multi_agent_system

# 安装依赖包（如果虚拟环境已激活）
.venv\Scripts\pip.exe install -r requirements.txt
```

### 4.2 本地测试入口（main.py）

**运行方式**：
```bash
.venv\Scripts\python.exe optimized_main.py
```

**数据存放规范**：
- 原始数据：`Fitabase Data 4.12.16-5.12.16/` 目录下
- 输入目录（标准）：`data/input/raw/`
- 输出目录：`optimized_results/`

**输出内容**：
- 按患者ID分文件夹（P_001、P_002、P_003）
- 每个患者包含：医生端/患者端/家属端/系统检查端
- 每个端包含：日报/周报/月报
- 日报包含：JSON结构化数据、PDF报告、可视化图表
- 模型缓存：`model_cache/baseline_history.csv`（在线学习基线历史）

### 4.3 HTTP接口服务入口（app.py）

**启动方式**：
```bash
.venv\Scripts\python.exe app.py
```

**服务信息**：
- 服务地址：`http://127.0.0.1:8000`
- 接口文档（Swagger）：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/health`

**核心接口**：

1. **健康检查接口**
   ```
   GET /health
   ```

2. **单患者健康评估接口**
   ```
   POST /api/agent/single_patient
   Content-Type: application/json
   
   {
     "patient_id": "P_001",
     "generate_report": true,
     "export_pdf": false
   }
   ```

3. **生成单日报告接口**
   ```
   POST /api/report/generate_daily
   Content-Type: application/json
   
   {
     "patient_id": "P_001",
     "report_date": "2016-04-15",
     "end_type": "all",
     "export_pdf": true
   }
   ```

4. **获取PDF下载链接**
   ```
   GET /api/report/get_pdf_url?patient_id=P_001&report_date=2016-04-15&end_type=doctor
   ```

5. **获取患者列表**
   ```
   GET /api/patient/list
   ```

**静态资源访问**：
- 所有生成的报告、PDF、图片都可以通过 `/static/` 路径访问
- 例如：`http://127.0.0.1:8000/static/P_001/doctor_end/daily/2016-04-15/2016-04-15_doctor.pdf`

## 五、若依框架集成方案

### 5.1 若依Python版（FastAPI）无缝集成

1. **集成方式**：将多智能体系统作为若依Python版的一个业务模块，直接import到项目中
2. **集成步骤**：
   - 将 `optimized_system/` 文件夹复制到若依的 `modules/` 目录下
   - 在若依的 `requirements.txt` 中添加本项目的依赖包
   - 修改 `config.py` 中的路径配置，适配若依的项目目录
   - 在 `cardiac_rehab/` 目录下新增 `api.py`，编写接口路由
   - 在若依的 `admin.py` 中注册定时任务

### 5.2 若依Java版（SpringBoot）跨语言集成

**推荐方案：HTTP微服务集成**

1. **部署方式**：将多智能体系统打包为独立的Python微服务（基于FastAPI）
2. **启动配置**：
   - Linux环境：在若依Java的启动脚本 `start.sh` 中添加Python服务启动命令
   - Windows环境：编写批处理脚本，先启动Python服务，再启动若依Java jar包
3. **数据传递**：Java服务通过 `RestTemplate`/`FeignClient` 调用Python微服务的HTTP接口

**示例Java FeignClient接口定义**：
```java
@FeignClient(name = "cardiac-rehab-agent", url = "${agent.service.url:http://127.0.0.1:8000}")
public interface CardiacRehabAgentClient {
    @PostMapping("/api/agent/single_patient")
    R<AgentResultVO> runSinglePatient(@RequestBody PatientDataDTO dto);

    @GetMapping("/api/report/get_pdf_url")
    R<String> getReportPdfUrl(@RequestParam("patientId") String patientId, 
                               @RequestParam("reportDate") String reportDate);
}
```

## 六、核心智能体职责与技术说明

### 6.1 大模型选型说明

V1.0版本采用**双轨制架构**，兼顾医疗专业性与数据安全性：
1. **核心规则引擎**：90%的核心业务逻辑基于硬编码的临床指南规则实现，不依赖大模型，确保结果稳定、可复现、无幻觉；
2. **辅助增强模块**：仅在「异常归因文本润色、个性化健康建议生成」2个场景可调用大模型，支持本地部署开源大模型、字节跳动豆包API、OpenAI API，可通过配置文件一键切换，默认关闭大模型调用。

### 6.2 核心智能体职责说明

| 智能体名称 | 核心职责 | 输入 | 输出 |
|----------|---------|------|------|
| **数据处理智能体** | 流式数据接入、清洗、时间对齐、特征提取、场景标签化 | 原始CSV/JSON/XLSX数据、患者基线 | 标准化分钟级宽表、数据质量标记 |
| **在线学习智能体** | 个性化基线初始化、贝叶斯在线增量更新、三级风险区间划分、健康评分计算 | 标准化宽表、患者基线、历史模型参数 | 动态基线、健康评分、病情评估结果 |
| **医学专业智能体** | 异常事件归因分析、并发症风险评估、医疗建议生成、临床指南适配 | 预警事件、指标数据、患者临床信息、指南规则库 | 归因结论、医疗建议、并发症风险评分 |
| **风险分级智能体** | 三级预警判定、高危事件识别、患者恶化优先级排序 | 健康评分、异常事件、医疗风险规则 | 预警等级、高危事件标记、患者排序列表 |
| **可视化智能体** | 多端定制化绘图、异常点标注、高危事件截图生成 | 指标数据、基线区间、异常点信息、绘图规范 | 全量可视化PNG图片、图表元数据 |
| **报告生成智能体** | 多端报告模板渲染、文本与图表整合、JSON/PDF格式导出 | 病情评估结果、医疗建议、可视化图片、报告模板 | 多端报告、结构化JSON报告、PDF文件 |

## 七、三端核心差异对照表

| 维度 | 医护端（医生/康复师） | 患者端（康复患者本人） | 家属端（患者监护家属） |
|------|---------------------|---------------------|---------------------|
| **核心定位** | 专业医疗决策辅助 | 个人康复自我管理 | 远程监护与风险预警 |
| **数据颗粒度** | 全量原始数据、分钟级时序数据、全指标明细 | 核心3项指标（心率、步数、睡眠）、日级汇总数据 | 核心5项监护指标、预警事件明细 |
| **专业度** | 全专业术语、临床指南关联、并发症风险分析、用药建议 | 无专业术语、通俗化解读、生活化健康指引 | 极简专业术语、监护护理建议、风险应对指引 |
| **核心内容** | 患者恶化排序、全指标趋势分析、异常归因、专业医疗建议、基线调整记录 | 健康评分、康复目标达成率、每日健康总结、个性化康复指引 | 核心指标趋势、高危事件实时预警、事件截图、护理建议 |
| **报告类型** | 日报/周报/月报全量专业版 | 日报/周报/月报简化版 | 日报精简版、高危事件专项报告 |
| **可视化内容** | 24小时多指标联合趋势图、异常热力图、预警分类饼图、基线更新轨迹图 | 简化心率趋势图（2区间）、目标达成率饼图、周度趋势简化图 | 核心指标趋势图、高危事件截图、预警时间线 |

## 十、V1.0版本已知局限与迭代方向

1. 目前仅支持3类心脏康复患者，后续可扩展高血压、糖尿病、脑卒中后遗症等慢病康复场景；
2. 大模型仅用于辅助文本生成，后续可扩展基于大模型的临床问答、康复方案智能调整；
3. 目前仅支持单实例部署，后续可扩展集群部署、负载均衡、高可用架构；
4. 目前仅支持结构化时序数据，后续可扩展心电数据、血压、血氧等更多生理指标。
